# NECTAR Estate UI

Веб-приложение для российского брокера, армянского брокера и администратора. Работает с backend [`nectar-be`](../nectar-be) (адрес в `VITE_API_URL`); данные, авторизация и все бизнес-правила — на сервере. Подробное описание проекта — в [`PROJECT_OVERVIEW.md`](../PROJECT_OVERVIEW.md).

## Сделка

1. Российский брокер создаёт запрос и отправляет его на проверку.
2. Администратор одобряет запрос (его видят армянские брокеры) или отклоняет с причиной.
3. Армянский брокер отправляет объекты как предложения.
4. Администратор одобряет предложение (его видит российский брокер) или отклоняет с причиной.
5. Российский брокер бронирует подходящие объекты и резервирует их; объект может быть только в одном активном резерве.
6. Администратор проводит финальную проверку: подтверждает продажу или возвращает резерв в работу с причиной.

Отклонённые запросы и предложения исправляются и отправляются повторно.

## Стек

React 19 · TypeScript · Vite · Tailwind CSS v4 · React Hook Form + Zod · react-icons

## Запуск

Требуется Node.js 22.12 или новее.

```bash
npm install
npm run dev
```

Приложение откроется в браузере на [http://localhost:5173](http://localhost:5173).

## Скрипты

| Команда             | Назначение                                     |
| ------------------- | ---------------------------------------------- |
| `npm run dev`       | dev-сервер с hot reload                        |
| `npm run build`     | проверка типов и production-сборка в `dist/`   |
| `npm run preview`   | локальный просмотр production-сборки           |
| `npm run typecheck` | проверка типов TypeScript                      |
| `npm test`          | unit-тесты                                     |
| `npm run test:e2e`  | e2e-тесты Playwright (сервер запускается сам)  |

Для e2e нужен браузер Playwright (`npx playwright install chromium`) либо установленный Chrome: `PW_CHANNEL=chrome npm run test:e2e`.

e2e-тесты работают с настоящим бэкендом (`VITE_API_URL` из `.env`, или `E2E_API_URL=http://localhost:4100/api` — тогда и приложение, и тесты ходят в него). Бэкенд должен быть засижен (`pnpm db:seed`, демо-админ `admin.demo@example.com`), разрешать origin `http://localhost:5180` в `CORS_ORIGIN` и доверять localhost (`TRUST_PROXY=loopback`): каждый тест шлёт свой `X-Forwarded-For`, чтобы не упереться в лимит попыток входа. Тесты создают заявки и компании, поэтому лучше запускать их на отдельной базе.

## Кабинеты

Роль определяется аккаунтом при входе; домашние страницы:

- `/broker/workspace` — российский брокер;
- `/partner/requests` — армянский брокер;
- `/admin/overview` — администратор.

## Структура

```text
src/
├── app/          # оболочка приложения, роутер, шапка
├── pages/        # страницы: components/ + utils/ внутри каждой
├── features/     # общие сценарии (панели, формы, редактор объекта)
├── components/   # переиспользуемые UI-компоненты и поля форм
├── api/          # RTK Query: эндпоинты backend по доменам
├── demo/         # типы и селекторы общего состояния (исторические имена «demo»)
└── utils/        # общие константы, хелперы, типы, Tailwind-классы
```
